## Decisions (and why)
- A point with zero valid citations is dropped, not moved to "uncertain": there is no message for the owner to check, so showing it would be showing an invented fact.
- Deleting a message clears the stored summary, so a summary can never cite a deleted message.
- Added a "Load sample messages" button (Messages screen) so judges can try the app in one tap; it imports the bundled synthetic dev set.
- Editing a draft changes only the guest-language text; the card then says the Nepali meaning may be out of date.
- T5 counts as correct only if Wi-Fi is NOT a point AND is listed under uncertain (strict reading of the brief).

## Learned (rules discovered the hard way — follow these from now on)
- Laptop has 6.1 GB RAM, CPU only. With the model loaded ~1 GB is free: keep one model loaded, keep `num_ctx` small (8192 max), don't run eval and heavy builds together.
- `gemma4:e2b` is 4.6 GB on disk here (4.6B params, Q4_K_M), not ~2.6 GB as the brief says. Report the measured number in README/EVAL.
- The model wrote `text_ne` in English when asked for a Korean draft. Prompt must say "Nepali in Devanagari script", and code must reject `*_ne` fields with no Devanagari.
- In the 6-message sample it cited the English and Nepali cooking-class messages but missed the Korean one → per-language recall is a real issue to measure.

- Runs are NOT deterministic even with temperature 0 + fixed seed (dev SCORE 1.30 / 1.55 / 1.65 on the same prompt). Always compare means of 2 runs; treat differences under ~0.1 as noise.
- Analysis takes 27–57s for 40 messages; a draft takes 6–8s.
- tsx scripts outside the repo need the `.mts` extension for top-level await.
- UI test recipe: `npx vite --port 5199` + scratchpad `ui.mjs` (playwright-core, `channel: "chrome"`).
- Biggest model weakness: incomplete citation lists (stops at ~5 IDs per point), not wrong themes.
